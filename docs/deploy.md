# Deploying the M365 Copilot Prompt Analyser

There are two supported paths:

1. **One-click "Deploy to Azure" button** — pulls prebuilt public images, no build tools required.
2. **`azd up`** — builds from source and provisions the same infra.

---

## 1. One-click button

### For end users (deploying an existing published build)

1. Click **Deploy to Azure** in the [README](../README.md).
2. Pick a subscription and **create/choose a resource group**.
3. Set a **dashboard admin password** (everything else has sensible defaults).
4. **Review + create.** Provisioning takes ~5–10 minutes.
5. Open the deployment's **Outputs → `dashboardUrl`** and sign in with `admin` + your password.
6. Go to **Settings** and connect Microsoft Graph (see [After deployment](#after-deployment)).

What gets created (all in your resource group):

| Resource | Purpose |
| --- | --- |
| Container Apps environment | Hosts the api + worker |
| `…-api-…` container app | Public dashboard + API (serves the React bundle) |
| `…-worker-…` container app | Background ingestion/scheduler |
| PostgreSQL flexible server | Stores prompts, users, licenses |
| Log Analytics workspace | Container logs |

Secrets you never have to handle: the **PostgreSQL password**, the **Fernet key** (encrypts the
Graph client secret at rest), and the **JWT signing key** are all generated by the template.

### For maintainers (one-time, so the button works for everyone)

The button can only pull **public** images. Publish them once:

1. Push this repository to `github.com/loryanstrant/M365Copilot-Prompt-Analyser`.
2. The **Publish container images** workflow (`.github/workflows/publish-images.yml`) runs on push
   to `main` (and on `v*` tags) and pushes two images to GHCR:
   - `ghcr.io/loryanstrant/M365Copilot-Prompt-Analyser/api`
   - `ghcr.io/loryanstrant/M365Copilot-Prompt-Analyser/worker`
3. **Make both packages public** (one time): repo **Packages** → open each package →
   **Package settings** → **Change visibility** → **Public**. Azure Container Apps then pulls them
   anonymously with no registry credentials.
4. Tag a release (`git tag v1.0.0 && git push --tags`) if you want the button to offer a pinned
   version instead of `latest`.

## 2. azd (build from source)

```powershell
azd env set POSTGRES_ADMIN_PASSWORD "<strong-password>"
azd env set FERNET_KEY "<fernet-key-or-any-string>"
azd env set SECRET_KEY "<random-secret>"
azd env set ADMIN_PASSWORD "<admin-password>"
azd up
```

`azd down` tears everything down.

## After deployment

The reporter needs an Entra app registration with **application** permissions:

- `AiEnterpriseInteraction.Read.All`
- `Directory.Read.All`

Grant admin consent, create a client secret, then in the dashboard:

1. **Settings** → a **guided first-run wizard** walks you through creating the app
   registration (with copy buttons and an optional one-shot PowerShell script). Enter the
   **Tenant ID**, **Client ID**, **Client Secret**, confirm the Copilot SKU id(s), and
   (optionally) a schedule + report-access group.
2. **Test connection** → **Run ingest now** (or start a **Backfill** for history).
3. Explore the dashboard.

The client secret is encrypted at rest with the Fernet key before it touches the database.

## Entra single sign-on (optional)

The dashboard is protected by the admin password by default. Entra sign-in adds read-only viewer
access with work accounts, while administration stays behind the password.

Sign-in is performed by the app itself rather than by the hosting platform, so it behaves the same
on Azure Container Apps, Docker on any host, or Kubernetes. Nothing needs configuring on the
platform, and there is no deploy-time setting for it.

**Prerequisite:** none beyond the app registration you already created for collecting data — the
same one is reused for sign-in.

**Setup, after deployment:**

1. Sign in as the admin and open **Settings**.
2. Copy the **redirect URI** shown there (it is
   `https://<your-dashboardUrl>/auth/oidc/callback`).
3. In the Entra portal, open the app registration → **Authentication → Add a platform → Web** and
   paste that redirect URI.
4. To restrict viewers to a security group, set the **report access group** in **Settings** and add
   a **groups** claim under **Token configuration** on the app registration. Without the claim the
   analyser falls back to an app-only Graph `checkMemberGroups` call using the permissions it
   already has. Non-members are refused (fail-closed).

Once the app registration details are saved, the sign-in page shows a **Sign in with Microsoft**
button.

**Behind a reverse proxy:** the app derives its public address from the request, honouring
`X-Forwarded-Proto` / `X-Forwarded-Host`. If your proxy does not send those, set `PUBLIC_BASE_URL`
(for example `https://prompts.contoso.com`) so the redirect URI matches what you registered.

## Updating a deployment

- **New build:** re-run the publish workflow (or push to `main`). Restart the container apps, or
  redeploy the template with the new `imageTag`, to pick up the new image.
- **Move the database:** point `DATABASE_URL` at any PostgreSQL — no code change.
